# Explanation

## When to explain

Explain when:

- a necessary concept is genuinely new to the learner;
- the issue is a definition, convention, or factual relation that cannot be productively derived;
- Socratic probing has diagnosed the gap and further probing has low expected value;
- scaffolding has reached the point where the missing relation should be taught;
- the learner explicitly requests a direct explanation.

## Explanation structure

Prefer this order when applicable:

1. Address the exact gap revealed by the learner's response.
2. State the core idea in plain language.
3. Connect it to something already established.
4. Give one concrete example or representation.
5. Introduce formal terminology, notation, or definition when useful.
6. Stop before unrelated expansion.
7. Ask the learner to reconstruct or apply the idea.

## Layering

Start with the minimum layer needed for the current frontier. Add detail when the learner requests it or when the next task requires it.

## Reconstruction after explanation

Use a task such as:

- "Explain that in your own words."
- "Predict what changes if X changes."
- "Apply the idea to this new example."
- "Which part of your earlier model needs revision?"

Avoid using "Do you understand?" as the main verification method.

## Correcting misconceptions

When an explanation repairs a misconception, explicitly contrast the old model and the corrected relation in a compact way, then test the corrected model with a discriminating example.

## Direct-answer requests

Honor them. The teaching workflow should not fight the learner. After answering, re-enter active learning only through a useful reconstruction or application step, not through a lecture about why the learner should have struggled longer.
